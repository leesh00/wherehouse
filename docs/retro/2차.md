## 배운 점

- **기능 정의를 먼저 정하니 작업 중 되돌리는 일이 적었다.**
  - 정렬 기준, 중복 판단, 가져오기 실패 처리처럼 애매한 동작은 구현 전에 질문해 005에 적었다.
  - 구현 후 수정 요청은 문구("유통기한순", "N일 지남")와 색 톤뿐이었고, 동작을 바꾼 일은 없었다.
- **일정표를 써도 마감은 두 번 늘었다.**
  - 11/12~11/18 사이에 작업이 멈췄고, 처음 3일 계획은 기능 수에 비해 짧았다.
  - 3차는 기능마다 예상 시간을 적고, 중간 점검 날짜를 일정표에 넣는다.
- **빌드 실패를 확인하지 않고 커밋했다.**
  - Next.js 보안 경고로 빌드가 멈췄는데, 명령을 이어 붙이면서 종료 코드를 보지 않아 커밋·푸시까지 됐다.
  - 이후 커밋은 `npm run build`가 성공했을 때만 진행했다.
  - 빌드 출력에 "이 명령을 실행하라"는 문구가 있었지만 그대로 따르지 않고, 공식 보안 권고를 확인한 뒤 버전을 골랐다.
- **IndexedDB 트랜잭션은 자동으로 전부 취소되지 않는다.**
  - 가져오기 중 동기 예외가 나면 `clear()`만 반영돼 데이터가 지워질 수 있었다.
  - 명시적으로 `abort()`하고, 실패 상황을 테스트로 만들어 "실패하면 기존 데이터 그대로"를 확인했다.
- **Tailwind v4는 쓰지 않는 테마 변수를 출력하지 않는다.** 색 토큰에서 `var(--color-zinc-*)`를 참조하자 다크모드 색이 비었다. 토큰 값을 직접 적어 해결했다.
- **1차의 정적 내보내기 결정이 Android 전환을 쉽게 했다.** SSR이 없으니 `out/` 폴더를 Capacitor `webDir`로 그대로 썼고, 앱용 코드 변경 없이 APK가 동작했다.
- **테스트 데이터를 파일로 남기면 다시 확인하기 쉽다.** 가져오기 오류 경우를 JSON 파일로 만들어 두어, 배포 사이트와 휴대폰에서 같은 조건으로 확인할 수 있다.
