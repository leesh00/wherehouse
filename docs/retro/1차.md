## 배운 점

- **배포를 먼저 하길 잘했다.** 빈 프로젝트를 먼저 배포하는 단계에서 Vercel 조직 권한 문제가 드러났다. 화면을 다 만든 뒤였다면 마지막에 원인 찾기가 겹쳤을 것이다.
- **상태를 종류별로 나누니 스토어가 작아졌다.**
  - 위치·재고 id는 URL에 두니 새로고침과 직접 링크(수정 화면 URL로 바로 진입)가 별도 코드 없이 동작했다.
  - 폼 값은 `useState`에 두어 저장이 실패해도 입력이 남는다.
- **저장 흐름 "어댑터 성공 → 스토어 갱신".** 화면과 DB가 어긋날 여지가 없다. 테스트도 어댑터만 하면 된다.
- **정적 내보내기 제약은 규칙으로 미리 막았다.** 동적 경로 대신 쿼리 파라미터를 쓰고, `useSearchParams`는 Suspense로 감쌌다. 그래서 빌드 에러 없이 통과했다.
- **최신 프레임워크 버전은 기억 대신 문서로 확인한다.**
  - Next 16은 템플릿 기본 설정(`cacheComponents` 등)이 달랐다.
  - 패키지에 포함된 문서(`node_modules/next/dist/docs`)를 먼저 읽었다.
- **레이아웃 확인은 눈과 숫자를 같이 쓴다.** flex 안의 input 넘침은 `scrollWidth`와 뷰포트 폭을 비교해 확인했다.
