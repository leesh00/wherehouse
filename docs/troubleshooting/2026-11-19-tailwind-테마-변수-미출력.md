# 다크모드 색 토큰이 적용되지 않음 (Tailwind v4 테마 변수)

## 문제

다크모드를 위해 `globals.css`에 의미별 색 토큰(`--bg`, `--primary` 등)을 만들고, 값을 Tailwind 팔레트 변수로 지정했다.

```css
:root {
  --bg: var(--color-white);
  --primary: var(--color-zinc-900);
}
```

다크모드로 열어 보니 배경이 계속 흰색이었다. 버튼·배지·경고 상자의 배경색도 모두 사라졌다. `matchMedia('(prefers-color-scheme: dark)')`는 `true`였다.

## 원인

Tailwind v4는 **실제로 쓰는 클래스에 필요한 테마 변수만** CSS로 출력한다.

- `bg-zinc-900` 같은 클래스를 모두 토큰 클래스(`bg-primary`)로 바꾸면서, `--color-zinc-900` 등을 쓰는 클래스가 하나도 남지 않았다.
- 그래서 이 변수들이 출력되지 않았고, `var(--color-zinc-900)`는 정의되지 않은 값이 됐다.
- 그 결과 배경색 같은 속성이 무효 처리돼 기본값(투명·흰색)으로 보였다.

## 시도한 것

1. 다크모드 스크린샷 확인 → 배경 흰색, 배지 배경 없음
2. 미디어 쿼리 확인 → 다크 맞음. 토큰 값 자체가 비어 있다고 판단

## 해결

토큰 값을 Tailwind 팔레트의 hex 값으로 직접 적었다. 예를 들어 `--primary: #18181b;`(zinc-900)처럼 쓴다. CSS 주석에 이유를 남겼다.

수정 후 다크·라이트 모두 정상으로 보였다. 대비도 계산해 확인했다. 본문, 보조 글자, 버튼, 배지, 경고 상자 모두 WCAG AA(4.5:1) 이상이었고, 가장 낮은 값이 6.2:1이었다.

## 배운 점

- Tailwind v4의 테마 변수는 "항상 있는 전역 변수"가 아니다. 사용하는 만큼만 출력된다. CSS에서 `var(--color-…)`를 직접 쓰면 그 변수를 쓰는 클래스가 없을 때 깨진다. 항상 출력하려면 `@theme static`을 쓰거나, 값을 직접 적는다.
- 색을 바꾸는 작업은 "미디어 쿼리가 맞는지"와 "변수 값이 실제로 있는지"를 따로 확인해야 원인을 빨리 좁힐 수 있다.
