# 001. 1차(MVP) 범위 축소

- 날짜: 2026-10-28
- 상태: 확정

## 배경

1차 마감까지 하루뿐이었다. 기획한 기능을 모두 넣으면 배포와 테스트까지 끝낼 수 없다. "동작하는 것을 배포까지"가 기능 수보다 중요하다고 판단했다.

## 선택지

| 선택지                           | 장점                                                         | 단점                                      |
| -------------------------------- | ------------------------------------------------------------ | ----------------------------------------- |
| 전체 기능을 1차에 구현           | 완성도 높은 첫 버전                                          | 마감 안에 배포·테스트를 못 끝낼 위험이 큼 |
| 핵심 흐름만 1차, 나머지 2차 이월 | 마감 안에 배포·테스트 완료 가능. 배포 파이프라인을 먼저 검증 | 1차 결과물 기능이 적음                    |

## 결정

1차는 홈, 목록, 등록, 수정, core/ 테스트, Vercel 배포만 한다.

- 홈: 위치 카드 3개(방, 부엌, 화장실), 탭하면 해당 위치 목록으로 이동
- 목록: 위치별 재고, 등록순
- 등록·수정: 유통기한은 입력만 받고 표시는 하지 않음
- 테스트: 저장소 어댑터의 저장·조회·수정

2차로 이월한 기능:

- 삭제, 검색, 정렬(유통기한·수량), 유통기한 임박 표시
- 중복 등록 경고, JSON 내보내기/가져오기
- 로그인, 서버, 알림, 위치 추가 UI, 다크모드
- (3차) 3D

## 이유

- 이 앱의 핵심 가치인 "어디에 무엇이 몇 개 있는지 기록하고 다시 찾기"는 등록·수정·목록만으로 검증할 수 있다.
- 배포를 가장 먼저 해서 빌드·배포 설정 문제를 초기에 발견하도록 순서를 잡았다(빈 프로젝트 배포 → 데이터 레이어 → 화면 → 재배포).
- 이월 기능도 데이터 모델에는 미리 반영했다. 예를 들어 `expiresAt` 필드와 위치 트리(`parentId`, `depth`)가 있다. 그래서 2차에 스키마를 바꾸지 않고 화면만 추가하면 된다.
